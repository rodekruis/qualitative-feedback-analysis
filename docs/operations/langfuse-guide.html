QFA in Langfuse

Langfuse is the tool that records every call that the QFA service makes to the language model (the AI model that reads and writes text). This page tells you what you can find in Langfuse, what you will not find, and where to look.

Start with the default Home dashboard

When you open a project in Langfuse, the Home page already shows most of what you need: cost, number of traces, usage per model, and scores over time. Look there first. Use the rest of this page when you need more detail.

You will not see feedback text here, by design

Langfuse receives only facts about each call: what kind of task, for which organization, with which model, how many tokens, the cost and the time. If you open a call, the Input and Output boxes are empty. This is correct, and nothing is broken.

  • Langfuse never receives the feedback text that a user sends.
  • Langfuse never receives the answer that the model writes.
  • The analysis results go back only to the system that called QFA.

The one exception is the quality tests at the end of this page. They use invented or anonymized test text, not real feedback.

How data gets there

Four things go to Langfuse

A request comes in from a calling system, for example EspoCRM. QFA calls the language model one or more times. After each call, QFA sends a short record to Langfuse. When a check by a second model runs, QFA also sends its scores. At startup, QFA sends a copy of its instructions to the model. When a person rates a result in EspoCRM, EspoCRM sends that rating.

Feedback text and model answers travel only on the top row. The dashed line to Langfuse carries no feedback text.

Words you will see

The Langfuse vocabulary

Trace
One request to QFA. Its ID is the same as the request ID that the caller receives.
Observation
One step inside a trace. In QFA, every observation is one call to the model.
Generation
The Langfuse type for an observation that is a model call.
Token
A piece of text, about three quarters of a word. Models charge per token.
Score
A number from 0 to 1 for the quality of a result, from a person or a second model.
User
In QFA, the organization (tenant) that sent the request, shown as a random string. It is not a person.
Tag
A label on a trace. QFA tags each trace with the task name, and adds judge for checks.
Prompt
The fixed instructions that QFA gives the model for a task. Langfuse keeps each version.

In more detail

Users, cost, scores and prompts

Users are organizations

The Users page lists every tenant that called QFA. A tenant is an organization with its own API key. Select a tenant to see all its traces, its token use and its cost.

Langfuse shows each tenant as a random string, not as a name. Langfuse also does not know the country. To link a string to a country, look up the tenant ID in the system that manages the API keys, for example the QFA tenant records or EspoCRM.

Cost

Each call shows its token count and its cost in US dollars. The dashboards add these up per day, per model and per tenant. QFA also keeps the same figures in its own database, and its usage report gives the official totals.

Scores

A person in EspoCRM can rate an AI result. EspoCRM sends this rating to the trace of that request as user_quality_score, from 0 (bad) to 1 (good).

For most tasks, a second model also checks the first model's work. It gives scores from 0 (poor) to 1 (excellent):

  • faithfulness: the result agrees with the feedback.
  • coverage: the result covers the main themes.
  • clarity: the result is easy to read.
  • quality_score: one overall score from these three.

For assign_codes, the scores are confidence_level_1 to confidence_level_3, one per level of the coding framework.

For detect_sensitive, the score is sensitivity_confidence: how sure the second model is that the sensitivity rating is right. If the check fails or does not run, the trace has no score.

Prompts and versions

The Prompts page shows the 12 instructions that QFA gives the model, for example summarize-single-system. When the team changes an instruction, a new version appears at the next start of the service. Each call shows which prompt and which version it used, so you can compare results before and after a change.

These prompts are fixed text from the code. They never contain feedback.

Using it for QFA

Ways to use Langfuse

Each row names the question, where to look, and an example. Use the dev project for tests and the prd project for live monitoring.

UseQuestion it answersHowExample
Release testing Is the new version as good as the old one? Run the quality test set on the new version in dev. Open Datasets and compare the scores with the last run. Each trace carries the version and commit in its metadata. recall_sensitive drops from 0.96 to 0.88 after a prompt change. The team stops the release and fixes the prompt first.
Health monitoring Is production running well today? In prd, read the Home dashboard each week. Watch the error count, cost per day, traces per day, and the scores over time. Cost per day doubles with the same number of traces. Open the expensive traces, find the model or task that changed, and act on it.
Model comparison Which model gives the best result for the price? Run the same test set with each model in dev. Compare the scores and the cost per model in Datasets and on the dashboard. Model B scores 0.02 lower on faithfulness than model A but costs half as much. The team decides if that loss is acceptable.
Prompt changes Did the new instructions help? Each call shows its prompt version. Group the scores by prompt version on the dashboard, or compare two test runs. clarity rises from 0.78 to 0.85 for summarize-single-system version 4.
User feedback Are people satisfied with the results? Check with the users why they are not happy with particular results. The score user_quality_score is below 0.6. Users seem not to be quite happy.
Per-tenant checks Does one organization see worse results? Filter by user (the tenant ID) and compare scores and errors with the rest. Then look up the country in another system. One tenant has twice the error rate of the others. The team finds that its feedback is in a language that the prompt handles badly.

All numbers in this table are invented examples.

Quality tests

Datasets and test runs

The team also uses Langfuse to test QFA before a release. A dataset is a fixed set of test feedback with the correct answers, for example which records are sensitive. A test run sends this set to QFA and compares each answer with the correct answer. The result appears under Datasets, with scores such as accuracy (share of correct answers) and recall_sensitive (share of sensitive records that QFA found). Here you do see text, but it is invented or anonymized test data.

Limits

What Langfuse does not show

  • The feedback text, and the answers that the model wrote.
  • Which person sent a request. Langfuse knows only the tenant ID.
  • The name or country of a tenant. You must derive these from another system.
  • Sessions. Each request is a separate trace.
  • Calls from before Langfuse was switched on for a project.
